# Task spec: offline country boundary asset

Work ONLY inside /home/rojo/dev/sos-numbers. Ruby is NOT installed. Use python3, stdlib only,
no pip installs. Do not create files other than the deliverables plus a cache file.

## Why

The app must resolve GPS coordinates to a country with NO network access. So it bundles a
simplified world boundary set and does point-in-polygon locally.

## Deliverables

1. `tools/gen_country_borders.py` - reproducible generator
2. `assets/geo/country_borders.json` - its output
3. Append a short "format" section to this spec file describing the final layout you chose,
   so the Dart side can be written against it.

## Source

Natural Earth admin-0 countries, 50m resolution:

    curl -sL 'https://raw.githubusercontent.com/nvkelso/natural-earth-vector/master/geojson/ne_50m_admin_0_countries.geojson' -o tools/ne50m.cache.geojson

If that URL 404s, try the `master` branch path variants or the 110m file as a fallback, but
prefer 50m for accuracy. Cache the download.

## Processing

- ISO code per feature: prefer `ISO_A2`; when it is `-99` or missing, fall back in order to
  `ISO_A2_EH`, `WB_A2`, then a hardcoded name -> alpha-2 patch dict (Natural Earth famously
  has -99 for France, Norway, Kosovo, Somaliland, N. Cyprus and a few others). Every emitted
  feature must have a real alpha-2 code. Log anything you had to drop.
- Merge features sharing an ISO code into one entry (multiple rings).
- Quantise coordinates to 3 decimal places (about 110 m) and drop consecutive duplicate points
  after rounding. Drop rings left with fewer than 4 points.
- Do NOT drop small rings by area blindly: island nations and city states must survive. If you
  need to shrink the file, prefer coarser quantisation over dropping rings, and never drop a
  ring if it is the only one left for that ISO code.
- Precompute a bounding box per country: `[min_lon, min_lat, max_lon, max_lat]`, used as a fast
  reject before the ray-cast test.
- Store integers, not floats, if it helps size: multiplying by 1000 and rounding is fine as long
  as you document the scale factor in the format section.
- Target final file size under 3 MB. Report the actual size.

## Output

Compact JSON (`separators=(',',':')`, no indent). Include a top-level `schema`, `source`,
`quantisation` / `scale` description, and the country list. Keys short since this is a bundled
asset, but the format section must document them unambiguously.

## Format (as built)

File: `assets/geo/country_borders.json`, single compact JSON object, UTF-8, no indent,
`separators=(',',':')`. Generated by `tools/gen_country_borders.py`
(`--build`, `--verify`; run with no flags = build).

### Top level

| Key | Type | Meaning |
|---|---|---|
| `schema` | int | Format version. Currently `2` (`1` had no `subunits`). Bump on any breaking change. |
| `source` | string | Human-readable source description. |
| `source_url` | string | Exact URL the geometry came from. |
| `scale` | int | `1000`. Coordinate multiplier — divide any stored coordinate by this to get degrees. |
| `quantisation` | string | Human-readable note on precision. |
| `encoding` | string | `"delta"`. See ring encoding below. |
| `ring_format` | string | Human-readable note, same content as below. |
| `bbox_format` | string | Human-readable note, same content as below. |
| `countries` | array | The data. Sorted ascending by `c`. Unchanged from schema 1. |
| `subunits_source` | string | Human-readable source of the overlay (admin-0 *map units*). |
| `subunits_source_url` | string | Exact URL the overlay geometry came from. |
| `subunits_note` | string | Human-readable note, same content as "Subunits overlay" below. |
| `subunits` | array | **Schema 2.** Overlay of overseas territories, same object shape as `countries`, sorted ascending by `c`. Tested **first**. |

### Country object

| Key | Type | Meaning |
|---|---|---|
| `c` | string | ISO 3166-1 alpha-2, always exactly 2 uppercase letters, unique in the array. |
| `n` | string | English country/territory name (display only, never a key). |
| `b` | `[int,int,int,int]` | Bounding box `[min_lon, min_lat, max_lon, max_lat]`, scaled ints. Fast reject before ray casting. |
| `r` | array of arrays | One or more rings. Every ring of a country — outer boundaries *and* holes — sits flat in this one list. |

The same object shape is used by both `countries` and `subunits`. A code appears in at most one
of the two arrays, never both.

### Ring encoding

Each ring is a **flat array of scaled ints**, delta encoded:

    [x0, y0, dx1, dy1, dx2, dy2, ...]

- The first pair is absolute: `lon = x0 / scale`, `lat = y0 / scale`.
- Every later pair is a delta from the **previous point**, not from the origin:
  `x[i] = x[i-1] + dx[i]`, `y[i] = y[i-1] + dy[i]`.
- Order is always **lon, lat** (x, y) — GeoJSON order, *not* lat, lon.
- Length is always even; point count is `length / 2`; minimum 3 points.
- Rings are **implicitly closed**: the closing point is not stored. Wrap from the last
  point back to the first when iterating edges.
- Winding order is meaningless — do not rely on it to tell holes from outers.

Delta encoding is purely a size optimisation (6.6 MB absolute → 2.6 MB delta) and costs one
running sum while decoding.

### Precision

- Coordinates are `round(degrees * 1000)`, i.e. 3 decimal places, ~110 m at the equator.
- Before quantising, rings are Douglas-Peucker simplified with `eps = 0.002` degrees (~220 m).
- Rings whose bbox extent is under `0.05` deg are **never simplified**, and rings under
  `0.004` deg are quantised **outward** from their centroid (ceil above, floor below) rather
  than to nearest, so sub-grid geometry (Vatican City, atolls, the Vatican-shaped hole in
  Italy) still contains its own interior instead of collapsing to a sliver. Such rings can be
  up to one grid cell (~110 m) larger than reality.
- No ring is ever dropped for being small, and no country is ever left with zero rings.
- Source geometry is Natural Earth **10m**, not 50m: at 50m the coastline generalisation puts
  Manhattan, Hong Kong Island and the European bank of the Bosphorus in the water, so New York,
  Hong Kong and Istanbul cannot resolve at any quantisation. 50m/110m remain as download
  fallbacks in the generator.

### Point-in-polygon algorithm (what the Dart side must do)

1. Scale the query point: `x = lon * scale`, `y = lat * scale` (keep as double).
2. For each country, reject immediately unless `b[0] <= x <= b[2] && b[1] <= y <= b[3]`.
3. Otherwise ray cast over **every ring of that country accumulated into one
   even-odd (odd winding) counter**, decoding deltas as you go:

       inside = false
       for each ring:
         for each edge (p[j] -> p[i]), j = i-1 wrapping at the ends:
           if ((yi > y) != (yj > y)) && (x < (xj - xi) * (y - yi) / (yj - yi) + xi):
             inside = !inside

   One shared counter across all rings is what makes holes work: a point in Lesotho crosses
   the ZA outer ring and the ZA hole, so it counts even and lands outside ZA, then matches LS
   on its own. Do **not** reset `inside` per ring, and do not special-case holes.
4. First (and normally only) country that returns true is the answer. No match means the point
   is at sea or in Antarctica-adjacent void — return null and fall back to the SIM/locale.

### Subunits overlay (schema 2) and the lookup order

**Why it exists.** Natural Earth admin-0 *countries* folds several inhabited overseas
territories into their parent state's feature even though they have their own ISO code and
their own emergency numbers. A phone in Kralendijk (Bonaire) therefore resolved to `NL` and was
shown **112**, when `BQ`'s real number is **911**; Mayotte, Cocos and Tokelau resolved to nothing
at all. Nine codes present in `assets/data/emergency_numbers.json` had no geometry:
`BQ CC CX GF GP MQ RE TK YT`.

**What it is.** `ne_10m_admin_0_map_units` is the same Natural Earth vintage with those
territories split out as their own features (identical parent outlines). The generator runs it
as a second pass through the *exact* same pipeline as `countries` (same Douglas-Peucker eps,
small-ring exemptions, quantisation, delta encoding, bbox) and emits the result as the top-level
`subunits` array.

**Membership is computed, not hardcoded.** A map-units feature is emitted into `subunits` iff:

1. it resolves to a real alpha-2 code (same `ISO_A2` → `ISO_A2_EH` → `WB_A2` → name-patch
   chain as `countries`), and
2. the admin-0 pass did **not** already emit that code, and
3. the code has its own entry in `assets/data/emergency_numbers.json`.

Rule 3 is deliberate: the overlay's only job is to hand the lookup a code with *better* numbers
than the parent's. A code with no dataset entry would make the app show nothing where it used
to show the parent's working number. Excluded by that rule at the time of writing: `BV` Bouvet
I. (uninhabited), `SJ` Svalbard (uses Norway's numbers), `XD` UNDOF Zone (user-assigned code,
not ISO). Features with no resolvable code at all (Korean DMZ halves, Paracel Is.) are skipped.
Every exclusion is logged by the generator with its reason. The current overlay is exactly the
nine codes above; re-running the generator against newer data may grow it.

**Geometry note.** A subunit's rings sit *inside* the parent's `countries` rings — e.g. Bonaire
is still part of `NL`'s geometry — so the parent match is not removed, it is *shadowed*. Nothing
was subtracted from `countries`; it is byte-identical to schema 1.

**Lookup order the Dart side MUST use:**

    1. for each entry in `subunits`  : bbox reject, else ray cast (algorithm above)
       → first hit is the answer (e.g. BQ)
    2. for each entry in `countries` : same
       → first hit is the answer (e.g. NL)
    3. no hit → null, fall back to network/SIM/locale

Precedence is explicit — `subunits` first, then `countries` — and must **not** be inferred from
array order or from merging the two arrays. Testing `countries` first would return the parent
and reintroduce the bug. A reader that only knows schema 1 can ignore `subunits` and gets the
old (parent) behaviour; a reader that knows schema 2 must test it first.

**Verification.** `--verify` runs three tables in this order and exits non-zero on any
failure: the ten territory coordinates from `SPEC_subunits.md` (plus one on-land companion for
each known source gap), six parent-capital checks that must be unchanged by the overlay, and the
original 32-case table. It also asserts, for every entry in both arrays: `b` equals the min/max
of the entry's own delta-decoded points, every ring length is even and `>= 6`, every value is an
int, codes are unique, and no code appears in both arrays.

**Known source gaps (not fixable in this asset).** Three of the spec's ten territory
coordinates lie outside the *raw* Natural Earth 10m polygon itself, so no pipeline setting can
make them resolve and the generator does not fabricate geometry to force it:

| Place | Coordinate | Why NE 10m misses it | Result |
|---|---|---|---|
| Mamoudzou, Mayotte | -12.780, 45.228 | NE coastline drawn ~850 m west of the real waterfront | null |
| Flying Fish Cove, Christmas I. | -10.422, 105.679 | ~2.1 km north of NE's northern tip of the island | null |
| Nukunonu, Tokelau | -9.169, -171.819 | atoll absent from NE 10m entirely; nearest ring (Fakaofo) is 70 km away | null |

These were null before the overlay and are null after it — never a *wrong* code. The
territories themselves resolve correctly from on-land points (Dzaoudzi → `YT`, Christmas I.
airport → `CX`, Fakaofo east rim → `TK`). `--verify` reports these three rows as `GAP` rather
than `FAIL` and they do not affect the exit code, but a wrong non-null answer for them would. If
the exact spec coordinates matter, the fix is a Dart-side "nearest polygon within N km" fallback
for null results, not asset geometry.

### Coverage notes and ISO caveats

- 239 codes in `countries` plus 9 in `subunits` (248 distinct). Includes dependencies and
  territories with their own alpha-2 (`HK`, `MO`, `GI`, `PR`, `NC`, `PF`, ...), so a hit is not
  always a sovereign state.
- `XK` (Kosovo) is a user-assigned code, not an official ISO 3166-1 entry.
- Entities with no ISO code are folded into the nearest de jure holder rather than dropped:
  Somaliland → `SO`, N. Cyprus / Akrotiri / Dhekelia / UN Buffer Zone → `CY`,
  Siachen Glacier → `IN`, Guantanamo Bay → `CU`, Bir Tawil → `SD`,
  Ashmore & Cartier + Coral Sea + Indian Ocean Territories → `AU`, Clipperton → `FR`,
  Spratlys → `VN`, Scarborough Reef → `PH`, Serranilla/Bajo Nuevo Banks → `CO`,
  Southern Patagonian Ice Field → `CL`, Brazilian I. → `BR`, Baikonur → `KZ`.
  These are pragmatic mappings for emergency-number lookup, not political claims. The Indian
  Ocean Territories ring stays `AU` in `countries`, but `CC` and `CX` in `subunits` shadow it,
  so Cocos and Christmas Island resolve to their own codes.
- Nothing crosses the antimeridian inside a single ring — Natural Earth already splits at
  ±180 — so no wrap handling is needed.
- Territorial waters are not modelled. A boat, an airport apron built on reclaimed land after
  the Natural Earth vintage, or a lagoon inside an atoll can all return null.
